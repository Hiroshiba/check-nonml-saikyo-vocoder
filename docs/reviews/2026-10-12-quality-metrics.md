# ローカル資産を使う追加評価の実装確認

2026-10-12。独立した実エージェント5人の実行ではなく、5観点での設計・コード見直しです。
モデルの品質優越や既存人間評定での校正を主張する記録ではありません。

## 第1回の見直しと修正

| 観点 | 指摘 | 反映 |
|---|---|---|
| 入出力 | HNM専用パラメータに依存しない方がよい | 任意方式のWAV/NPY一覧と既存固定比較の保存波形を入力にした |
| 測定 | ViSQOL公式CLIのWAV制約を確認すべき | v3.3.3のwav_reader.ccを読んでPCM16のみと確認。float WAVを渡す案をやめ、同一量子化・範囲超過拒否にした |
| 実行 | モデル資産の未取得を成功に見せない | 未設定・利用不可・対象外・失敗を別状態にし、nullと理由を残す |
| 統計 | 反復を独立したMOS評定や音声数と扱わない | 初回値を採点値、同一seedの反復を時間測定として分離した |
| 批評 | JVS未取得なのに人間評価との一致を捏造しない | 明示的な既存評定入力を要求。人工順位を人間評定扱いする入力を拒否した |

## 第2回の見直しと修正

- SCOREQのスカラーモデルを参照あり埋め込みと取り違えないよう、fixed_nmrのファイル名と出力次元を確認する。
- ECAPAは公式の生埋め込み経路だけを実装し、分類器や全体正規化の重みを不要にした。構造は公式設定に合わせ、strictにロードする。
- ViSQOLの起動・モデル読込・WAV入出力込みの時間を、モデル常駐のPython評価器と混同しない。子プロセスCPU時間は測定していないと表示する。
- 特徴距離はgroup別に相関と評定対内最近傍を示し、全組合せを独立標本としてp値を出さない。
- 途中で入力ファイルが変わった場合に別条件の値を混ぜないよう、同じ実行内のファイルhashを照合する。
- 新しい出力先を要求し、保存済み比較の採否や音声を上書きしない。追加HTMLから元の音声付きレポートへリンクする。

## ローカル実行で確認したこと

Python 3.13.5のコンテナで追加モジュールをコンパイルし、通常の評価関数を手元の音声で実行した。
リポジトリが指定するPython 3.12での確認はPRのCIに委ねる。
既存logging_utils.pyはGit blob `9af5d0908dfd76cf835e556e4e011d83da895407` と同一内容を用いた。

- 約6.34秒のeSpeak由来の原音・加工音でERB計測を初回＋5反復した。原音自身は0、加工音は3.308928521787821 dB。
  加工音の反復中央値は約0.02435秒。この実装・この音声だけの診断であり、以前の試作実装の時間とは同一視しない。
- ERBだけ要求した実行は終了コード0。資産のないSCOREQ・ViSQOL・ECAPAも要求した実行は終了コード1となり、該当9行の品質値はnullだった。
- 入出力の長さ不一致は失敗行として残り、値はnull、終了コード1だった。
- 人工順位を人間評定として渡す入力は失敗、値はnull、終了コード1だった。既存人間評定を得たという主張はしていない。
- JSON/HTMLの生成とベースとの差の表示を確認した。WAVの非音声チャンク警告と、意図的な失敗のスタックトレースをログに残した。
