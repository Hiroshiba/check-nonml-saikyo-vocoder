# 既存方式比較の評価再開を修正

## #29の後で必要と判断した理由

確認したmainは `86853a42b61ccbdad996ccfeb0deff58e3d33bd3`。#29の標準7方式のCIとPagesデプロイは成功していた。一方、`references/evaluate.py` は途中評価を書き出すだけで読み戻していなかった。

このため、再開時に全音響指標・MOSを再計算し、音響のみの再実行では既存MOSを `not_requested` で上書きする。また再開直後に中断すると、まだ巡回していない行の途中評価が消える。評価側では `--retry-failed` の有無も区別していなかった。

## 修正

- 条件記録のSHA-256と評価入力が一致する保存済み行だけを再利用する。生成波形は再利用時も実ファイルのSHA-256を確認する。
- 原音のMOS、音響指標、各方式のMOSを逐次保存する。再開時は未評価分だけを計測し、音響のみの再実行でMOSを消さない。MOSを開始する前にも音響評価を保存する。
- 失敗した評価は明示的な `--retry-failed` 指定時だけ再試行する。元の行は `evaluation_history.json` に残し、結果保存コマンドでもコピーする。

標準6方式の追加・WORLD・任意DACの選択、波形の生成、測定指標・MOSのモデル条件は変更しない。`USER_INSTRUCTIONS.md`、`BASELINE.json`、過去の実験、テストとワークフローの変更・削除は含めない。

## 手元で実行した確認

#29最終CI（run `38285792166`）の成果物 `11763650897` を取得。ZIPのSHA-256は `cee5d508e76cda374037737da5900771f9045aad781e3c969aa01c022667c1a3`。同梱ソースのGit treeはmainと同じ `c32838f9ddc4a1c5957fb3bfc12c3cf3e2e968f4` だった。

保存済みの原音2本・生成波形14本を新しいローカル実行先で再評価した。新たな音声合成や品質採用実験ではない。Python 3.13.5、NumPy 2.3.5、SciPy 1.17.0、pystoi 0.4.1を使用し、リポジトリ指定のPython 3.12とは異なる。UTMOSv2は未導入なので、実際の初期化失敗経路を確認した。

| 操作 | 確認結果 |
|---|---|
| 初回の保存波形評価 | 音響14行を計算。原音を含むMOS16行は初期化失敗・null、終了コード1 |
| 同条件で再開 | 音響14行を再利用。MOS呼出し0回。失敗状態を維持し終了コード1。全評価行・音声例は前回と一致 |
| `--retry-failed` | 音響14行は再利用。MOS16行だけ再試行し、旧失敗16行を履歴へ保存。未導入のままなので終了コード1 |
| 音響のみの評価関数実行 | 原音2＋方式14のMOS記録16行を全て保持 |
| 結果保存・一覧生成 | 音声付きHTMLと失敗履歴を保存。履歴のコピー元とSHA-256一致。サイト生成・内部リンク検査が終了コード0 |
| 静的確認 | 変更Pythonのコンパイルとソース行数確認が終了コード0 |

テストスイートやモックによる偽のMOS値は追加していない。確認は通常の比較・保存コマンドと、保存された実波形に対する評価関数の実行で行った。

## 未確認と既存結果の扱い

実UTMOSv2モデルによる新規MOS推論・成功値の再利用、固定120音声全体、全開発候補との統合実行はこの手元確認では未実施。PRの通常CIは標準7方式の実再合成と保存経路を確認するが、`--smoke --no-mos` のためMOS実測の代わりにはならない。

ソースSHAと途中保存形式を変更したため、修正前の実行先へ上書きして再開しない。修正後の比較は新しい出力先で開始する。公開済みの結果HTML・JSONは変更しない。
