# Windows再計算のベース再現確認

2026-10-12、正式120録音の探索比較を実行中に行った読み取り専用の監査。実行中のコード・候補・入力は変更していない。以下は途中時点の観測で、120録音の完了確認ではない。

比較元は `experiments/2026-10-12/noise-envelope/results/run-001/results.json` の `candidate`（採用後のHNM v2に相当）、比較先は `runs/noise-screen-120/parts/*.json` の `hnm`（今回の正式ベース）。録音IDとseed 0〜7を対応させ、両方で実測済みの共通音響スカラーを比較した。

## 出典と実装

今回の実行コードは進行役が固定したコミット `12aaf69`。実行契約に記録された `noise_screen.py` のSHA-256は `ada7ed38f5c67b7892f1a18af226d738400934607dd4adb9e403b5ca7bdbf667`。

今回の契約にある6つの `hnm*.py` のSHA-256は、旧比較の候補契約にある同名ファイルとすべて一致した。合成実装 `hnm_synthesis.py` は双方とも `937721cd363f06afa3bf4c20c1ff182a8c337c4b19ac9f4b57314f6adea6b44c`。Windowsへの移動によって別のベースを使用した形跡は認められない。

## 途中結果の照合

監査時点で全候補・全seedが終わった録音は33件。完了途中の録音を含め、ベースの272録音×seed行について36種類の共通スカラーを比較できた。開始済み録音の未実行seed行は49件あり、これを失敗・成功のいずれにも加算していない。

| 指標 | 旧結果との差の絶対値の最大 |
|---|---:|
| 全帯域10 ms包絡NRMSE | 3.6082×10⁻¹⁶ |
| 全帯域40 ms包絡NRMSE | 3.3307×10⁻¹⁶ |
| 多解像度スペクトル誤差 dB | 2.2204×10⁻¹⁴ |
| 帯域エネルギー誤差 dB | 1.4710×10⁻¹⁵ |
| RMS音量比 dB | 2.9421×10⁻¹⁵ |
| 最大振幅 | 1.6653×10⁻¹⁵ |
| 全36指標の中の最大差（300–1000 Hz・40 ms対数RMS誤差） | 1.1052×10⁻¹² |

この範囲では差は浮動小数点計算の丸めの大きさにとどまった。波形配列そのものを旧実行とビット単位で比較した結果ではないため、「同一波形ハッシュを確認した」とは記載しない。MOSとeSTOIはこの照合の対象外であり、MOS実行環境の同等性まで保証しない。

## 失敗行と集計の扱い

同じ監査時点の探索比較には `failed` seed行がなかった。従って、レビューで指摘した「seed 0の波形保存等に失敗した場合、先に算出済みの値が失敗行に残り、共通集約関数が数値を有効扱いし得る」問題は、この途中結果には発生していない。実行中に修正すると出典が変わるため、修正は実行後に行い、今回使用した版と区別する。

最終結果では全行の状態を再確認する。失敗行が存在する場合は値をそのまま平均へ混ぜず、成功行のみの有効数と予定数を併記し、失敗内容を残す。修正後のコードで実行したことにしない。別実行のWORLDで報告されたDLLのエクスポート不備は、今回のHNM再現確認には含めていない。

## 音響120録音完了後の追加監査

上の33録音時点の記録を保持したまま、英語音響の全件完了後に再確認した。HNM v2、A、B、C、D、Eはそれぞれ960/960 seed行が `measured`、合計5,760/5,760。各録音・方式に重複のないseed 0〜7がちょうど8個存在し、失敗・未実行・欠落は0だった。したがって本実行の音響値には、失敗行に残った値を数える懸念は発現していない。

旧候補v2と現ベースの対比較は120録音×8 seed＝960組。共通36スカラーのすべてに960対の有限値があり、計34,560個の数値対を比較した。最大絶対差は以下の通り。

|---|---:|
| 全帯域10 ms包絡NRMSE | 5.5511×10⁻¹⁶ |
| 全帯域40 ms包絡NRMSE | 4.0939×10⁻¹⁶ |
| 多解像度スペクトル誤差 dB | 6.3949×10⁻¹⁴ |
| 帯域エネルギー誤差 dB | 2.4425×10⁻¹⁵ |
| RMS音量比 dB | 2.9698×10⁻¹⁵ |

| 全36指標の最大差（300–1000 Hz・40 ms対数RMS誤差） | 1.8786×10⁻¹² |

`hnm.py`、`hnm_analysis.py`、`hnm_control.py`、`hnm_diagnostics.py`、`hnm_parameters.py`、`hnm_synthesis.py` の6個すべてで、現実行契約のSHAと旧候補契約のSHAが一致することも再確認した。この全件監査も旧波形とのビット一致そのものを主張せず、同一実装・固定入力に対する音響指標の再現確認と位置付ける。MOSは別段階で、音響全件完了からMOS全件完了を推測しない。
